# KYTHEREX Field Demo

Standalone mobile-first sales demo for KYTHEREX timber procurement analytics. Single `index.html`, React 18 from CDN, zero build step. Deployed via GitHub Pages.

## Architecture

Three views behind a MAP / COMPETITION / PRICING switcher. MAP is the single map-centric product view
with an expandable drawer for bid analysis.

- **Header:** Mill selector (4 demo mills) + Season selector (4 seasons), on one row
- **MAP:** SVG map of real county and state outlines (`GEO`, generated by `scripts/build-geo.mjs`),
  profit rings in statute miles, FIA county inventory bubbles, 11 sawmills from `mills_mt_pnw.json`
- **Economics bar:** Species price range, margin at the mill's typical haul, moisture gap
- **Drawer:** Bid recommendation card + what-if sliders (diesel, stumpage, MC, target margin)
- **Supply panel:** Species mix, ownership, growth-to-drain, competing mills
- **Bottom bar:** Species selector + CTA button
- **COMPETITION:** Leaflet (CARTO dark tiles), 3 mills, 18 demo sales classified at runtime
- **PRICING:** FSOT pricing/ROI, mill-specific subscription estimate, contact

## Model rules (see docs/solutions/data-integrity/bid-model-and-map-geometry.md)
- `evaluate()` is the only bid/cost computation; `moistureGap()` the only moisture computation.
- Slider defaults come from `millDefaults(mill)`. Never hardcode one mill's values.
- `BANDS` and `classify()` are shared by MAP and COMPETITION. Never pre-bake sale classes.
- Market prices: BBER Q3 2026 publishes a low/high range. Show the range; never call the midpoint an average.
- Do not hand-edit the `GEO` blob. Change `scripts/build-geo.mjs` and rerun it.

## Financial Source of Truth

All pricing/ROI numbers match Financial Source of Truth v2.3 (they live only in the `FSOT` block):
- Pricing: $0.25-$0.75/MBF sliding scale (tiers in the FSOT block)
- ROI: 10-25x (NOT 3x-60x)
- Savings: $116K-$290K per mill (at 25K MBF/yr, 1-2.5% improvement)
- Avg annual cost: ~$12,500
- TAM: $15M national

## Skill routing

### Compound Engineering (CE) Commands
CE commands chain multiple skills into gated pipelines. Each phase must pass before
the next begins. Failures are fixed in-place with atomic commits.

- Full verification (review + QA + offline browser checks) → invoke ce-verify
- Verified ship (review + QA + ship) → invoke ce-ship
- Full deploy (review + QA + ship + land) → invoke ce-deploy
- Hotfix fast lane (ship only) → invoke ce-hotfix
- Plan and build (autoplan + TDD implementation) → invoke ce-plan
- Configure CE stack → invoke ce-setup

### Project-specific notes
- **Browser test runner.** Runtime remains a single-file React-from-CDN demo.
  Maintainer checks use `npm ci`, `npx playwright install chromium`, and `npm test`.
  The offline/update check uses isolated contexts and writes to `test-results/`.
  Use `CHROMIUM_EXECUTABLE` for an existing local browser. See README.md.
- **Knowledge seed.** Established patterns and solved problems live in `docs/solutions/`.
  The learnings-researcher reads these during `/ce-plan` and `/ce-review`.
- **Map geometry.** `npm ci && node scripts/build-geo.mjs` rewrites the `GEO` blob in index.html
  between the `GEO:BEGIN` / `GEO:END` markers.

### Custom deploy hooks
- Pre-merge: none (no build step)
- Deploy trigger: automatic on push to main (GitHub Pages picks up within ~30-60s)
- Deploy status: poll production URL until new `index.html` etag/content is served
- Health check: production URL returns 200 AND contains expected version/build marker
- **Service worker updates:** Online navigations refresh HTML and retain it for
  offline use. Keep cache-version bumps for changed precached assets or worker
  behavior; the existing hook still bumps it when index.html is staged. Verify
  `npm test` before shipping. Cache cleanup must affect only `kytherex-demo-*`,
  never every cache on the shared GitHub Pages origin. See
  `docs/solutions/configuration-issues/pwa-service-worker-cache-staleness.md`.
